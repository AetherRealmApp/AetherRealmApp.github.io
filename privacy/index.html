Privacy Policy

Effective date: 18 September 2026 · REALM 1.2.3 (versionCode 6) · applicationId app.aetherrealm.realm

This policy describes REALM, a personal growth Android application. It covers the Google Play package app.aetherrealm.realm version 1.2.3 (6). Where Early Access sideload builds (launcher name REALM EA, package app.aetherrealm.realm.web) process the same kinds of data, the same practices apply.

Who we are

REALM does not currently publish a separate public support email. Contact uses the Support page. Account deletion uses in-app Delete Account on REALM 1.2.3, or the private form on the Account & Data Deletion page. Do not post a Google email in a public GitHub issue.

What REALM processes

REALM requires verified Google sign-in to create a cloud-backed account. Your Realm account is linked to the Google identity verified by the authentication backend.

  • Account identifiers: Google identity used to sign in; REALM user id; username; referral code.
  • Profile and referral: qualified referrals, ranking metrics (username, referral code, qualified referrals, rank).
  • Progression: server-validated AWAKEN records, recovery snapshot (Realm day, Essence, streak and related progress), selected Realm preference.
  • Living Grove / Aether: environment selection and local presentation state. Living Grove is free and bundled.
  • Device-local: language, reminder preference, onboarding flags, local backups you export, and a locally generated Realm display identifier.

Why

We process this data to operate REALM: authenticate you, keep one Realm profile per Google identity, record AWAKEN history, maintain referral relationships (which are server-authoritative), show optional rankings, and restore progress after reinstall when you sign back in with the same Google identity.

Authentication

Sign-in uses Google through Supabase Auth. Google authenticates you; REALM receives the verified identity needed to attach one account. REALM does not receive your Google password.

Third-party providers

  • Google — sign-in identity, and Google Play if you install from Play (distribution, device compatibility, and any future Play-billed purchases).
  • Supabase — authentication sessions, account profile, referral state, AWAKEN records, recovery snapshots, and entitlement records when those exist.
  • GitHub — only if you contact us via Issues on the public website repository for support. Account deletion email is not collected through public issues.

REALM 1.2.3 does not include advertising SDKs, Firebase Analytics, Crashlytics, Sentry, or similar third-party analytics/crash packages.

Purchases

Living Grove is free. Premium Realms are Coming Soon. REALM 1.2.3 does not currently offer in-app purchase checkout, prices, or restore-purchases in the client. If purchasing is enabled in a later version, Google Play would process those payments under Google’s terms; REALM would keep a server-side entitlement record needed to unlock a world you already own.

Storage and security

Cloud account data is stored in REALM’s backend (Supabase) with access scoped to the signed-in user. Local progress and preferences use the app’s private storage (including SharedPreferences) on your device. Android backup for local Realm progress is disabled in V1 so a device transfer does not silently copy that file. Manual export creates a JSON backup you choose to save outside the app.

Sharing and notifications

Share Realm generates a card locally and opens the Android share sheet. REALM does not choose the destination. Reminders use local Android notifications for the end of the current 24-hour Core cycle. You can decline permission or disable reminders in Profile or system settings.

Retention

Local data remains until you clear app data, uninstall, or complete in-app account deletion, subject to Android behavior. Cloud account data remains until you delete the account in the app or a web deletion request is completed. Public ranking rows that display your username are removed when the account is deleted. We do not run advertising profiles. Backup files you exported live wherever you saved them; uninstall does not delete those files.

Account and data deletion

REALM 1.2.3 includes an in-app account deletion control on Profile: Delete Account / Hesabımı Sil. It sits next to Sign out and is a separate action. Sign-out ends the session on that device; it does not delete the cloud account. In-app deletion requires two confirmations, then deletes only the signed-in user’s cloud account. If you no longer have the app, use the public Account & Data Deletion page. That page uses a private form; it does not ask you to publish your Google email in a GitHub issue.

Open Account & Data Deletion

Children

REALM is not directed at children under 13. We do not knowingly create accounts for children under 13. If you believe a child provided data, use the deletion page.

Changes

If this policy changes, the effective date at the top of this page will be updated. Material changes will be reflected here before they apply to new data practices in a later app version.
